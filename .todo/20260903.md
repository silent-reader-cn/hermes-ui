## [已收口] live 工具卡劈词修复 — 文本 reveal 未完成时 flush 兜底断点把同一句劈开

**类型**：问题类（live 渲染 / 时间线断点时序）

**位置**：
- `lib/features/chat/chat_controller.dart:1790-1835` — `_appendToStreamingMessage`（追加 text 时原无条件建兜底 text 断点，start=已 flush 长度）
- `lib/features/chat/chat_controller.dart:1905` — `_handleInterimAssistant` 调 `_appendToStreamingMessage`（interim 新段落，需建点）
- `lib/features/chat/chat_providers.dart:329-540` — `liveTimelineProvider`（按断点 start 对 content 切片渲染）

**范围**：仅 live 流式回合内文本段与工具卡的交错。不涉及完成态（transcript 按消息渲染，天然正确）；不涉及 think 行、聚合开关语义、重连/replay 去重。

**复现**（会话 `7ea92838441b` 消息 `#160298`，2026-09-03 12:18 实机截图）：agent 消息「好喵，这是个新的方向/一致性问题。柚子先明确：…先摸清侧栏工具栏和窄屏导航的实现。」+ 句末并行 2 个 `read_file` 为同一条 assistant 消息。实证链条（探针 `test/features/chat/live_timeline_flush_wordsplit_probe_test.dart` + 源码 + 后端日志）：
1. **后端 SSE 顺序正确**：Hermes 先推完整文本 token（`_emit_interim_assistant_message` / `stream_delta_callback`），`tool_start_callback` 在工具真正执行时才触发（hermes-agent `conversation_loop.py:7445-7475`、`tool_executor.py:1061-1067`）→ 文本全量先到
2. **客户端 reveal 逐词消费**（48ms/档位）：文本 token 全到但 content 只 flush 到「一」（~13 字符）时，工具事件到达 → `_appendToolCall` 建 `tools` 断点
3. **原 bug**：后续 flush 走 `_appendToStreamingMessage` 兜底断点，`_ensureTimelinePoint(text, current.content?.length)` **用已 flush 进度建 text 断点** → 断点序列 `text(0) → tools → text(13)` → `liveTimelineProvider` 按断点切片把同一句在「一」「致」之间劈开、中间插工具卡
4. 探针证实：文本全到但 reveal 中途工具事件到达 → 修复前 `live:text` 条目 = 2（劈两段），修复后 = 1（完整一句）

**现状 vs 预期**：
- 现状（修复前）：flush 路径按「已 flush 长度」建兜底 text 断点 → 「一致性问题」的「一」「致」之间被 tools 折叠卡劈开；完成态无此问题（按消息渲染）
- 预期：句子完整输出完，工具卡排在句子边界后；模型真在句中发工具时按真实事件序劈（可接受）

**根因**：`_appendToStreamingMessage` 兜底断点用 `current.content?.length`（flush 进度）而非缓冲全量。text 段边界本应在 token 事件到达时定义（`_appendAssistantToken`），flush/reveal 只是推进 content，不该新建断点。

**修复（已合入）**：
- `_appendToStreamingMessage` 加 `establishPoint` 参数（默认 false）：flush/reveal 路径不建 text 断点 → 段在 token 到达时已定义，content 随 reveal 增长，工具卡自然排句后
- 仅 `_handleInterimAssistant`（interim_assistant 新段落，`\n\n` 分隔符追加）传 `establishPoint: true`，start 取缓冲全量 `_currentStreamingContent().length`，与 token 路径 1385 语义一致
- 回归测试：`test/features/chat/live_timeline_flush_wordsplit_probe_test.dart`（2 例：reveal 中途工具到达不劈 + reveal 完成后基线不回归）

**验收**：
1. ✅ 探针复现（修复前 text 条目=2）→ 修复后 =1，整句完整、工具卡 1 张在后
2. ✅ 既有 live 时间线测试全绿（`live_timeline_interleave/reconnect/range`、`chat_reconnect_dedupe`、`chat_error_recovery`、`chat_lockscreen_reveal`、`chat_sync`、`chat_streaming_scroll` 等 26+ 例）
3. ✅ 全量 `flutter test` 2208 绿（~3 跳过为预置）
4. ✅ `flutter analyze` 零告警
