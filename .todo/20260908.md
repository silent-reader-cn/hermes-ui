- 根因（四重，均带源码行号实证）：

  - R2 recovery 闩锁：transport error 置 checking 后预算烧尽无人复位，#29 解锁主动探活前置 `recovery == idle` 被永久跳过 → 解锁也救不回（死锁闭环）。
  - R3 解锁探活 one-shot：解锁瞬间网络未就绪 → 失败即转 forceReconnect 白烧预算，无重试。
  - R4 onClosed 不复位 recovery（静默断开族闩锁）。
- 交付（main @ 1966afe，5 文件 +538/-6）：
  - F1 resumed 重置恢复状态：解锁 = 人类在场 → `_reconnectAttempts=0` + 退避定时器清理 + recovery 非 idle 复位 idle + fullReconnect 冷却重置。

  - F3 预算耗尽哨兵：`recoverySentinelInterval=60s` 周期 WARN `Recovery exhausted, re-probing` + `isThrottledFallback` 探活自愈（失败不重建流），探活成功自动解除并自毁；`_finishStream`/dispose 同步撤哨兵。
  - F4 onClosed 复位 recovery 闩锁（非完成态）。
  - 配置：`ChatWatchdogConfig` 新增 `recoverySentinelInterval` / `resumeProbeRetries` / `resumeProbeRetryDelay`（测试可 override）。
